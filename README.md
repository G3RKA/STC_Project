# STC Project

Тестовое задание для компании СТЦ: библиотека на C++, которая в отдельных потоках читает байты из источника, декодирует каждый байт в строку по заданному формату и передаёт результат в приёмник. Есть модульные тесты на GoogleTest/GoogleMock и документация к коду.

## Задание

1. Реализовать класс, который в отдельном потоке (запускается и останавливается через API класса) читает байты из source, конвертирует их в строковые символы и передаёт результат конвертации в sink. Source и sink — устройства ввода и вывода, предпочтительно с интерфейсом `QIODevice`.

   Байт, прочитанный из source, состоит из битов type (6-й и 7-й), кодирующих тип данных, и битов data (0–5), хранящих данные:
   - если type = `0b00`, то data — беззнаковое целое;
   - если type = `0b01`, то data — знаковое целое;
   - если type = `0b10`, то data — одна из букв латинского алфавита (`'a'` = `0b000000`, `'b'` = `0b000001`, `'c'` = `0b000010`, `'d'` = `0b000011` и т. д.).
2. Интерфейсы source и sink.
3. Тесты с использованием gtest и gmock и их сборка через CMake.
4. Документация к коду.

Всё, что не указано, отдаётся на усмотрение исполнителя.

## Формат байта

```
 7   6   5   4   3   2   1   0
[type ] [         data          ]
```

| type | Значение data | Результат |
|---|---|---|
| `00` | беззнаковое целое 0…63 | `"0"` … `"63"` |
| `01` | знаковое 6-битное целое −32…31 (дополнительный код) | `"-32"` … `"31"` |
| `10` | буква: 0 → `a`, 1 → `b`, …, 25 → `z` | `"a"` … `"z"`, при data > 25 — `"UND"` |
| `11` | не определён заданием | `"NULL"` |

Примеры: `0b00000101` → `"5"`, `0b01111111` → `"-1"`, `0b10000010` → `"c"`, `0b11000000` → `"NULL"`.

Варианты `UND` и `NULL` — решение исполнителя для случаев, которые задание не описывает.

## Как работает

- **`Source` и `Sink`** — абстрактные интерфейсы с методами `Read(char*, int64_t)` и `Write(char*, int64_t)`. Их можно реализовать поверх файла, сокета, `QIODevice` и т. п. `Read` возвращает число прочитанных байт или `-1`, если данных пока нет.
- **`ByteProcessor`** управляет рабочими потоками:
  - `StartNewWork(Source*, Sink*)` запускает новый `std::thread` и возвращает его `thread::id`;
  - `StopExistingWork(id)` останавливает конкретный поток;
  - `StopAllExisitingWorks()` останавливает все потоки, деструктор делает то же самое;
  - `JoinWorkIfExists(id)` ждёт завершения потока.
- Каждый поток в цикле читает из источника по одному байту, декодирует его и пишет в приёмник строку в буфере фиксированного размера 5 байт (с завершающим нулём). Если данных нет, поток ждёт секунду и пробует снова.
- Остановка — через флаг `std::atomic<bool>` в структуре управления потоком, после чего поток присоединяется (`join`).
- Одновременно можно запускать несколько потоков с разными парами источник/приёмник.

## Тесты

Тесты используют моки `MockSource` и `MockSink`: источник по очереди отдаёт заранее заданные байты, а затем «нет данных», приёмник проверяет последовательность записанных строк (`InSequence` + `StrEq`).

| Тест | Что проверяет |
|---|---|
| `WrongDataInput` | байты с type `11` дают `"NULL"`, буквы с data > 25 — `"UND"` |
| `CorrectDataInputCase1` | беззнаковые целые |
| `CorrectDataInputCase2` | знаковые целые |
| `CorrectDataInputCase3` | латинские буквы |

GoogleTest 1.17.0 скачивается автоматически через `FetchContent`.

## Сборка и запуск

Нужны CMake 4.0 или новее, MSVC и доступ в интернет при первой конфигурации (для загрузки GoogleTest).

В Visual Studio или VS Code с CMake Tools достаточно открыть папку и выбрать пресет `x64-debug`. Из командной строки (Developer Command Prompt для Visual Studio):

```bash
cmake --preset x64-debug
cmake --build out/build/x64-debug
out/build/x64-debug/Testing/RunTests
```

Сборка проверена в Visual Studio 2026 (MSVC, x64) с пресетом `x64-debug`: все 4 теста проходят.
